## 2. 原因

前回の修正は `parse_meal_text()` 等の単体テストを通過していたが、GitHub Actionsの実行経路では `build_daily_payload()` がPDFから日別JSONを再生成し、既存の `site/data/daily-menus.json` を置き換えていた。テストした分類ルールと公開されるデータの間に、手動確認済みデータを保持する統合処理がなかった。

そのため、11月18日の正解データはリポジトリ内の初期JSONには存在しても、Actionsが再解析した公開JSONではPDF抽出結果に置き換わっていた。

## 3. 今回の修正

- `site/data/daily-menu-overrides.json` を新設し、11月18日の朝食・昼食の正解データを保存。
- `apply_daily_overrides()` を追加し、PDF解析後・アレルゲン上書き前に、手動確認済みの食事だけを優先適用。
- 同一日付のうち未指定の食事は自動抽出結果を維持する（今回は夕食）。
- PDF取得に失敗して自動抽出が0件でも、手動確定データが存在すればそれを出力できる。
- GitHub Actionsの実行コマンドに `--daily-overrides site/data/daily-menu-overrides.json` を追加。
- ISO形式の日付 `YYYY-MM-DD` も日付解析で受け付けるよう修正。
- 自動抽出結果にわざと誤った11月18日データを入れたテストを追加し、正解データへ置き換わることを検証。

## 4. テスト

`python -m pytest -q tests/test_daily_parser.py tests/test_daily_overrides.py tests/test_update_menus.py` を実行し、34件すべて成功。

`tests/test_app.py` はこの作業環境に Flask がインストールされていないため、今回のテスト範囲には含めていない。

## 5. 未解決事項

今回の手動上書きで、2026年11月18日の朝食・昼食は次回のActions実行後も正解データが優先される。一方、他の日付のPDF抽出結果を全件正しいと確認したわけではない。ユーザー提供JSONでは、11月の朝食Bが全日空であるなど、追加検証を要する構造的な異常がある。実際のPDF原本を取得して日付・食事・A/Bの各セルを照合する作業が必要。

アレルゲンは11月の90食すべて未確認であり、PDFの赤丸を人が確認して `allergen-overrides.json` に登録するまで安全・非該当とは表示しない。
